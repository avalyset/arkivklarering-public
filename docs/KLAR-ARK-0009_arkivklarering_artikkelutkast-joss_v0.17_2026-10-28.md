# arkivklarering: clearance-first processing of Norwegian local-radio and oral-history audio

**Author:** Eirik Botten Nicolaysen, EcoDeco AS (ORCID 0009-0001-9188-6788)
**Software:** `arkivklarering` 1.0.0 (code tag `testkjoring-v12`)
**Software archive:** Zenodo, 10.5281/zenodo.23723667 (the full git history is deposited separately with restricted access: DOI 10.5281/zenodo.23723450)
**License:** AGPL-3.0-or-later; a commercial licence is available from the rights holder

## Summary

A digitised local-radio or oral-history recording cannot be published until someone has checked it for personal data and third-party music. In Norwegian local archives, staff and volunteers do this by listening to every hour. In collections of thousands of hours, that listening is the bottleneck, not digitisation or transcription. `arkivklarering` is a local Python pipeline that proposes what a person should review before publication. It segments audio into speech, music and other sound, and transcribes the speech segments in two layers with NB-Whisper large [@K20; @K21] through whisper.cpp [@K51]. It flags possible personal data in both layers (person and place names, dates, phone numbers, national identity numbers and sensitive keywords) and drafts a catalogue record with a local language model. It exports WebVTT [@K29], OHMS XML [@K34], IIIF Presentation 3 [@K30] and MMIF [@K10]. The tool deletes and edits nothing: every output is a suggestion, and a person makes every decision. All processing runs locally, and the audio never leaves the machine.

## Statement of need

The problem is clearance, not search. The tool is designed to be judged by clearance outcomes: recall and precision against full human listening, and reviewer time per recording. Search quality is not the target, and a missing flag is never treated as a guarantee. This framing and its priority are registered on OSF [@osf_fbme7, under embargo until 2027-10-26]. These outcomes require archive material and have not yet been measured; the benchmarks reported below measure the components on public test splits. The target audience is the people who clear Norwegian local-radio, museum and oral-history collections for publication, and researchers who want to test whether machine suggestions can safely shorten that listening.

Three properties of this material shape the tool. First, recordings contain unreviewed personal data and rights-encumbered music, so they cannot be sent to cloud services. Second, speech is in Bokmål, Nynorsk and dialect. The NB-Whisper model cards list Nynorsk as a language [@K20; @K21], whereas the published Norwegian Presidio setup covers Bokmål only [@K28]. Third, the output has to arrive in formats that archives already use: OHMS for oral history, and IIIF and WebVTT for presentation.

Related archive projects apply automatic speech recognition to radio and television collections for text search or enrichment [@K71; @K72; @K73]. `arkivklarering` addresses the step before that: deciding what may be published at all.

## State of the field

The nearest open framework is CLAMS, an open-source platform developed at Brandeis University with GBH Archives [@K09]. Its interchange format, MMIF, is a data format for passing analysis results between CLAMS apps, and each annotation view in an MMIF file records metadata about the application that created it [@K10; @K13]. The Audiovisual Metadata Platform (AMP) combines automated mechanisms with human labour in one workflow [@K05; @K06]. `arkivklarering` adopts that idea: each human step is meant to become an explicit approval point, but the approval interface has not been built. The Nunn Center's SpeakEZ produces raw Whisper transcripts and a draft OHMS index, but it is an in-house, closed system [@K16]. We use it as a model, not as a component, and export OHMS XML whose format is tested against the archived schema version 5.4 [@K34]. FIX IT+ is a crowdsourcing platform on which users correct machine transcripts line by line while listening [@K17]; `arkivklarering` has no correction or review interface yet. For personal data, Presidio provides the detector framework [@K24], and the CLEANUP guide by NR and NAV shows a Bokmål setup [@K26; @K28]. We combine Presidio with the spaCy model `nb_core_news_md` 3.8.0 [@K53] and with NB-BERT-base-ner, which is fine-tuned on NorNE [@K23; @K38].

**Build versus contribute.** The scholarly contribution of `arkivklarering` is a clearance procedure and its measurement, not a new analysis component. The procedure decides which segments are sent to transcription, combines the flags from two transcript layers so that recall comes before precision, and is tested against preregistered thresholds on public Norwegian test splits. We built it as a small, separate package rather than as a contribution to CLAMS or AMP, for three reasons that follow from its decision records. First, the evaluation is bound to one code base: the preregistration, the deviation log and the run metadata refer to its commit identifiers and tags, and the tool has its own repository, decision records and preregistration so that its purpose and plans are not mixed with those of other projects. Second, all processing must run on the clearing institution's own machine, and the audio must not leave it, so the tool is a Python package with a command-line interface, and its external components (whisper.cpp, a separate environment for inaSpeechSegmenter and a local ollama server) run on the same machine. Third, the clearance logic rests on specific choices that the preregistered tests measure together as one pipeline (H2 measures the flags after segmentation and transcription): NB-Whisper in two layers for Bokmål and Nynorsk, flagging in both layers, and a union of flags without a score threshold. These are reasons for the shape of this tool, not shortcomings that we have demonstrated in CLAMS or AMP.

To make the results usable with CLAMS, `arkivklarering` writes MMIF 1.2.0 as an export instead of defining its own exchange format, and the test suite checks that export against the MMIF schema. Several things have not been done. The components are not CLAMS apps, and the application identifiers in the MMIF views are placeholders, because no CLAMS app is registered. The components do not exchange data through MMIF internally. The export has not been used in a CLAMS workflow. The repository contains no CLAMS app, and no contribution to CLAMS or AMP is recorded in it. Whether the clearance steps could be packaged as CLAMS apps has not been assessed.

## Software design

**Segment before transcribing.** Only speech segments go to Whisper. Music becomes a "suggested cut" and is never transcribed. The reason is that music contains nothing to transcribe and that any text produced there could be mistaken for content, not that hallucination has been demonstrated there: in our own test on silence, noise and music, the models produced no prose: with `-nt`, both layers wrote only the special token `<|nocaptions|>`, and before `-nt` the verbatim layer wrote ".". Koenecke et al. found hallucinated phrases in roughly 1% of transcriptions, more often for speakers with longer non-vocal durations [@K01]. That risk lies inside speech segments, so the rule does not remove it, and every transcript still needs human review. The default segmenter is inaSpeechSegmenter 0.8.0, whose code is MIT-licensed [@K119]. inaVAMOS [@K18], which segmented the preregistered runs H1 and H2, is kept only as an optional extra for reproducing them, because its licence is research-only. The cost is that inaSpeechSegmenter has no speech-over-music class, so the flag "music under speech, check rights" is no longer produced. On 60 development segments (396.9 s), the two segmenters agreed on 92.9% of seconds.

**Two layers, union of flags.** The raw layer uses the verbatim model, which writes lower case without punctuation and serves as the audit trail. The normalised layer uses the standard model, which produces readable text [@K20; @K21]. Name recognition depends heavily on capitalisation, so both layers are flagged. The flags are merged as a union without a score threshold, and flags in the two layers are paired when their DTW word times overlap (tolerance 0.5 s). Recall comes before precision: a missed name can reach publication, whereas a false flag costs a reviewer a few seconds.

**Local and verifiable.** The two Whisper model files are not downloaded by the code and are checked against recorded sha256 values before use. NB-BERT-base-ner, the inaSpeechSegmenter weights and the optional pyannote model are downloaded on first use. The catalogue draft (title, people, places, keywords and per-segment summaries) is produced by Borealis-open 4B through a local ollama server [@K52; @K48], and the code refuses any server address other than loopback. Suggestions that appear neither in the transcript nor in the flags are discarded and logged. Optional speaker diarisation uses pyannote [@K80; @K86] and labels speakers anonymously; no speaker is identified.

**Evaluation inside the code base.** Test splits can be loaded only with the identifier of a registered preregistration. Test runs start from a tagged code state through a wrapper that refuses a modified working tree and writes run metadata. This is meant to make every number in this paper traceable to the code that produced it.

## Research impact statement

There is no realised impact yet: no publications use the software, there are no external users, and it is not integrated elsewhere. A museum pilot is planned under a separate preregistration, which has not been written, and no pilot data have been processed.

The evidence offered consists of preregistered benchmarks on public Norwegian test splits, registered on OSF [@osf_hc83q, under embargo until 2027-10-26]. H1 and H2 are the primary outcomes; H3 and H4 are secondary. A threshold "holds clearly" when the 95% interval bound is also on the right side of it.

- **H1, transcription (NB Samtale test [@K102; @K99], 252 segments, 51 speakers):** the raw layer with the matching written standard has a corpus WER of 0.127 (95% speaker-cluster bootstrap 0.112–0.144; threshold ≤ 0.25). The normalised layer has 0.337 (0.305–0.373), which mostly measures normalisation rather than recognition. Forcing Nynorsk on Bokmål segments raises the raw WER from 0.111 to 0.315.
- **H2, flag survival (NPSC test [@K94; @K114], 1,995 segments, 3.95 h):** the share of reference flags that survive transcription is 0.913 for persons (346/379; Wilson 0.880–0.937; threshold ≥ 0.85) and 0.856 for places (172/201; 0.800–0.898, lower bound 0.80047; threshold ≥ 0.80). All five H2 thresholds hold on the point estimate, and four hold clearly. The raw layer alone reaches 0.749 for persons and 0.607 for places.
- **H3, name recognition (NorNE test [@K100; @K38], 3,450 sentences):** recall is 0.975–1.000 on the original text but 0.50–0.69 on lower-case text without punctuation. Precision is lowest for Nynorsk persons, at 0.733. All eight thresholds (recall and precision for persons and places in each written standard) hold on the point estimate, and five hold clearly.
- **H4 (human-read test script):** not carried out in v1.0 (deviation AV-27). The test script and the patterns in the privacy engine were written by the same author, and only one person would have read it aloud, so the test would not have given external validity. An external test on spontaneous dialect speech outside NB-Whisper's training data (NB Tale module 3 [@K108]) is planned for v1.1 under a separate preregistration (KLAR-PREREG-0003). Categories with no natural occurrences in H1–H3 are therefore not measured on speech in v1.0.

These numbers are optimistic, and their limits are part of the result. NB-Whisper's model card lists NPSC among its datasets without naming splits [@K20], so overlap with the NPSC test split can be neither confirmed nor ruled out. The NB-Whisper paper lists the Stortinget Speech Corpus, also without splits [@K92]; that corpus keeps the NPSC evaluation and test meetings aside [@K98]. The NB Samtale reference began as the output of a speech recognition system from the National Library of Norway's AI lab and was then corrected and reviewed by hand [@K99], which may favour NB-Whisper. The H2 reference is the flagging engine's own output on human transcripts, and H3 uses written text. Nothing has been measured on real archive audio, and the catalogue draft has not been validated. The licence of the inaSpeechSegmenter weights is unclear [@K119]. All 36 deviations from the plan are logged, including a foreknowledge field set wrongly on OSF and a choice of interval method for H3 made after the results were known.

The public repository holds the release tree as a single commit. The full git history, which the preregistration, the run metadata, the code tags and the timestamps refer to, is deposited on Zenodo with restricted access and access on request (DOI 10.5281/zenodo.23723450), because it contains seven fictional phone numbers in allocated number ranges (AV-29). The repository holds the reproduction scripts and the identities of the data. The materials behind every H1–H3 figure above are in the repository: the per-segment result files and the run metadata in `eval/test/` (commit, tags, and a check that the code was unchanged since `testkjoring-v2`, the tag the runs were made from), and `scripts/rapporter_intervaller.py`, which recomputes the intervals from those files. These figures are the preregistered measurements from those test runs; H1 and H2 were segmented with inaVAMOS, and H3 is text, so it was not segmented. On 2026-10-27 they were recomputed from the stored outputs with `scripts/rapporter_intervaller.py` at commit `9ded8d8`, and they match: the H1 corpus WER of both layers, the H2 survival shares, and the H3 recall and precision ranges. H1 and H2 cannot be re-run with the default segmenter, inaSpeechSegmenter, without becoming a different measurement, so we do not claim that the v1.0 pipeline produces these figures. The datasets are pinned by revision (see the note under the references).
